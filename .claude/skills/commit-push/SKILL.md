# コミット & プッシュ

## 原則

- **コミットしたら必ず `origin` へプッシュする。** バックアップを兼ねているのでローカルに置いて止めない。
- **コミット・プッシュは作者の指示があったときだけ**行う（勝手にコミットしない）。
  指示されたら**コミットとプッシュを最後まで済ませる**。
- 作業ブランチは **`dev`**。

## 手順

### 1. 現状を把握する

```
git status
git diff
git log --oneline -5
```

未追跡ファイルも見る。`codex-task.md` / `codex-watch.ps1` / `CLAUDE.local.md` /
`local.properties` は `.gitignore` 済み（＝上がらないのが正しい）。

### 2. 機能単位に分割する

作者の方針は「**作業ごと、つまりシステムごとに個別でコミット**」。
1回の作業で複数のシステムに触れていたら分けてコミットする。例:

```
銃システム: 射撃演出の実装と、銃定義のgunpack JSON化
ビルド: アセット自動同期タスクとソースエンコーディングの固定
プロジェクト運用: セッション開始時にアーキテクチャ設計を自動注入するフック
```

`<領域>: <何をしたか>` の形が既存の履歴で使われている。踏襲する。

### 3. プッシュ前チェック（省略しない）

追跡ファイルに**ローカル固有情報**（絶対パス・ユーザー名・マシン固有のパス）が
混ざっていないか確認する。そうした情報は `CLAUDE.local.md` / `local.properties`
（どちらも `.gitignore` 済み）に置く。

```bash
git diff --cached | grep -nF -e 'C:\Users' -e 'D:\Minecraft' -e 'r0319'
```

**`-F`（固定文字列）と単一引用符で書くこと。** この環境の grep には2つの罠がある:

- `-i` と `-F` を併用すると **grep 自体が core dump する**（パイプの中だと失敗が隠れ、
  「検出なし」に見えてしまう）。`-i` は付けない。
- `-E` で `\\` を使ったバックスラッシュのエスケープが**マッチしない**。`-F` を使う。

`net/r0319` / `net.r0319`（パッケージ名）は正常なヒットなので `| grep -v` で除いてよい。

ヒットしたら、それが**意図的に公開してよいものか**を判断する。判断がつかなければ作者に聞く。
あわせて、`.geo.json` / `.png` / `.animation.json` / `.ogg` などアセットの差分が
意図したものか（`syncGunAssets` が同期した結果か）も見る。

### 4. コミットメッセージ

**日本語**で書く。「何を」だけでなく**「なぜそうしたか」を本文に書く**。これが一番大事。

```
<領域>: <何をしたか（1行・50字程度）>

<なぜそうしたか。どういう問題があって、どう解決したか。
検討して採用しなかった案があればそれも1行で。>

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

複数行メッセージは heredoc で渡す（PowerShell なら単一引用符のヒアストリング `@'...'@`、
閉じの `'@` は必ず行頭）。

### 5. プッシュ

```
git push origin dev
```

初回や新ブランチなら `-u` を付ける。**ここまでやって初めて完了**。
プッシュ結果（コミットハッシュ・ブランチ）を作者に報告する。

## やらないこと

- `--no-verify` でフックを飛ばさない。フックが落ちたら原因を直す。
- `--amend` より新しいコミットを優先する（履歴がバックアップを兼ねているため）。
- `push --force` は使わない。必要になったら作者に確認する。
- `main` へ直接コミットしない（作業ブランチは `dev`）。
