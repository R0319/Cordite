# アセット反映（作者のBlockbench作業をゲームへ）

## 大前提: コピーはしない

`syncGunAssets` Gradleタスクが作業フォルダ（`local.properties` の `cordite.assetDir`。
実際のパスは git管理外の `CLAUDE.local.md` を参照）から `src/main/resources/assets/cordite/` へ
**自動でコピーする**。`processResources` が依存しているので `build` / `runClient` のたびに走る。

- **ファイルを手でコピーしない**（二重管理になる）
- **アニメーションの登録コードを書かない**（`GunModelCache` が自動検出する）
- **`build.gradle` を編集しない**（銃やアニメを増やしても不要）

したがってこのスキルの仕事は **①検証 → ②ビルド → ③報告** の3つだけ。

## ① 検証（ビルド前にやる）

ビルドは時間がかかる。**壊れたまま回すと時間を捨てる**ので先に静的検証する。

`mc-asset-validator` エージェントに投げる。渡す情報:
- 何を更新したと言われたか（銃ID・クリップ名・ファイル種別）
- 作業フォルダのパスと、`src/main/resources/assets/cordite/` の現状

自分でやる場合の最低確認（詳細は `mc-asset-validator` の定義に全項目がある）:

1. **クリップ名が標準名か** — `animation.<gunId>.<名前>` の `<名前>` が
   `idle` / `take_out` / `fire` / `fire_empty` / `reload` / `reload_empty` /
   `inspect` / `inspect_empty` / `eject` のどれか。それ以外は**作ってもコードが拾わない**。
2. **`sound_effects` が空 `{}` になっていないか** — Blockbenchのエクスポートで中身が消える既知の罠。
   「音が鳴らない」の再発原因はほぼこれ。**コード側では直せない**ので作者に戻す。
3. **`effect` 名の `.ogg` が実在するか** — `sounds/gun/` を見る。`.mp3` は同期対象外。
   `sounds.json` は `generateSoundsJson` が自動補完するので手で書かない。
4. **ロケーターの親子** — `idle_view` は `root` の**外**、`iron_view` は `root` の**子**、
   `muzzle_flash` と `root` が存在するか。

## ② ビルド

`build-check` スキルの手順に従う（`clean` 禁止・パイプ禁止・JDK21）。要点だけ再掲:

```
./gradlew build          # Windowsは gradlew.bat
```

- **`clean` を使わない**。`build/moddev/` の実行用ファイルが消えて `runClient` が壊れる。
- **パイプで成否を判定しない**。`BUILD SUCCESSFUL` の有無で見る。
- ログに `[Cordite]` で始まる行が出る。`sounds.json にエントリを追加` / アセット同期スキップ /
  読み込み失敗の警告はここに出るので**必ず拾って報告する**。

失敗したら `build-check` の既知エラー表で分類し、コード側の問題なら `codex-impl` へ渡す。

## ③ 報告（作者は実機で確認する）

ビルドが通ったら、作者が `runClient` で見るべきポイントを**チェックリスト形式**で渡す。
過去の実績上、この形が一番効率がいい:

```
- リロード後のちらつきが消えたか
- 三人称でリロードモーションが漏れなくなったか（F5で切り替え）
- /cordite give <銃ID> で取得できるか
- インベントリのアイコンが正しいか
```

同時に、検証で見つかった項目を**担当付き**で伝える:

- `[作者]` — Blockbench側で直すもの（キーフレーム、ボーン名、クリップ名、`sound_effects`）
- `[コード]` — 実装側で直すもの（→ `codex-impl` で Codex に渡す）
- `[要判断]` — どちらで直すか相談が要るもの

## やらないこと

- **見た目の数値を決め打ちしない**。一人称の位置/回転/スケール、カメラ・ロケーター座標、
  アイコンサイズは**作者が実機で調整する領域**。画面外に出るなどの構造的ミスは指摘してよいが、
  「もう少し右」のような調整を自分で繰り返さない（ゲーム画面を見られないため）。
- **アセットファイルを生成・改変しない**。`.geo.json` / `.png` / `.animation.json` / `.ogg` は
  作者の制作物。読み込む側のコードだけを扱う。
