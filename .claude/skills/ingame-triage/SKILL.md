# 実機フィードバックのトリアージ

作者は `runClient` で確認し、**複数の症状をまとめて口語で**投げてくる。例:

> モデルもんだいなし。アニメーションはリロードモーションが終わった後に数ミリ秒だけ描画が
> おかしくなってる。三人称に１人称のときのアニメーションが再生されている。hudも異常なし。

これを**1件ずつ独立した課題に割り**、原因を特定し、担当を決めるのがこのスキル。

## 手順

### 1. 症状を分解して列挙する

「問題なし」と言われた項目も**明示的に消し込む**（次に同じ確認を繰り返さないため）。
曖昧な表現は原文のまま残し、こちらの解釈を併記する（誤読して別のものを直すのが一番の無駄）。

### 2. 担当を判定する — ここが最重要

| 判定 | 症状の性質 | 対応 |
|-----|-----------|------|
| **[作者]** | 位置・角度・大きさが「ちょっとズレてる」「もう少し〜」 | **触らない**。作者が実機で調整する領域だと伝えて返す |
| **[作者]** | Blockbench側の成果物の問題（キーフレーム欠落、ボーン名、クリップ名） | 何をどう直すか具体的に伝えて返す |
| **[コード]** | 条件分岐・状態遷移・タイミング・同期の誤り | 原因箇所を特定 → `codex-impl` で Codex に渡す |
| **[仕様]** | どうあるべきか決まっていない | `docs/specs/` `docs/design/` を確認し、未定義なら作者に方針を聞く |

**見た目の数値を当てずっぽうで直して繰り返し調整する、をやらない。** ゲーム画面を直接見られないため、
その往復は必ず無駄になる。構造的ミス（画面外に出る、親子関係が逆）は指摘・修正してよい。

### 3. 原因を特定する

既知パターン（このプロジェクトで実際に起きたもの）を先に当てる:

| 症状 | 典型的な原因 | 見るファイル |
|-----|------------|------------|
| 三人称なのに一人称のアニメが再生される | 描画コンテキストの判定漏れ | `client/render/GunItemRenderer.java`（`ItemDisplayContext`） |
| 三人称でもレティクル/HUDが出る | 視点判定が無い | `client/GunHudOverlay.java`（`options.getCameraType().isFirstPerson()`） |
| アニメ終了直後に一瞬描画が乱れる | 終了フレームの状態更新順（先頭キーフレームに戻るのが1フレーム見える） | `client/render/GunItemRenderer.java` / `client/anim/GunActionPlayback.java` |
| 発砲音が二重に聞こえる | サーバー配信の発射音とアニメの `sound_effects` の重複 | `client/anim/GunAnimationSoundPlayer.java`（既知名は握り潰す＝名前がズレると素通り） |
| アニメの音が鳴らない | `sound_effects` が空 `{}` ／ `.ogg` 不在 ／ `.mp3` を指している | **[作者]** 側が多い。ログの `[Cordite]` WARN を見る |
| サイトが覗けない/カメラが戻る | `idle_view` `iron_view` の親子関係（`idle_view` は `root` の外、`iron_view` は `root` の子） | `geo.json` **[作者]** / `client/render/GunItemRenderer.java` |
| 弾道が見えない | 近すぎる弾を描かない距離設定、または弾速 | `client/render/TracerRenderer.java`（`MIN_CAMERA_DISTANCE`） |
| コマンドのタブ補完は出るが実行できない | Brigadier の引数型が値を受けられない（`StringArgumentType.word()` は `:` を含められない） | `command/CorditeCommands.java` |
| 弾数表示の違和感 | チャンバー分（+1）の扱い | `client/GunHudOverlay.java` / `item/gun/GunItem.java` |

当たらなければ `mc-researcher` で調査、クラッシュ/例外があれば `mc-log-analyzer` に投げる。
サーバー権威・同期に関わる変更が絡むなら修正後に `mc-reviewer` を通す。

### 4. 出力

症状ごとに1ブロックで、日本語・簡潔に:

```
### 1. リロード後に一瞬描画が乱れる  [コード]
原因: リロード完了状態の更新より先に弾切れ上書き判定が走り、終了フレームが1フレーム見える
該当: client/render/GunItemRenderer.java:NNN
対応: 状態更新の順序を入れ替える → codex-task.md へ
```

最後に**まとめ**を置く: `[コード]` の件数（→ Codexへ渡す）、`[作者]` の件数（→ 作者の作業）、
`[仕様]` で判断を仰ぎたいこと。

### 5. 直したあと

修正が入ったら、作者が実機で見るための**確認チェックリスト**を渡す（`asset-apply` の ③ と同じ形式）。
症状と1対1で対応させると、次の実機確認の報告がそのまま次のトリアージ入力になる。
