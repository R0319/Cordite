# 銃モデルの生成（tools/modelgen）

作者の指摘は**一度言われたら二度と言わせない**ために、下の「指摘チェックリスト」に足していく。
新しい指摘を受けたら、直すのと同じコミットでこのファイルと
[07-model-assets.md の「形の読み違いの記録と対策」](../../../docs/specs/07-model-assets.md#形の読み違いの記録と対策-仮) に記録する。

## 0. 担当範囲（作者の許可 2026-10-15）

- モデルの形・テクスチャ（生成した物）は Claude が作ってよい。採否は作者が決める。
- **見た目・配置の数値（一人称の位置/回転、ロケーター、照準線の高さ等）も Claude が直してよい**。ただし必ず
  確認作業（下の 4.）を入れ、何をどう変えたかを報告する。決め打ちで繰り返さない。

## 1. 着手前: 資料は多角的に集める

1 枚の真横写真だけで作らない（M79 の照尺を真横の写真 1 枚で作り、細い棒になった。作者の指摘「サイトは違う形」）。

| 集めるもの | 何に使うか |
|----------|-----------|
| 真横の写真（白背景・高解像度） | 側面形のトレース（`photo_trace.Silhouette`） |
| 斜め・前・後ろ・上からの写真 | **幅・断面の丸み・左右非対称の部品**（排莢口・ハンドル・つまみ）、薄い部品の正体（板か枠か棒か） |
| 可動部の別の状態の写真（開いた・倒した・外した） | 回転軸と動き方（M249 のハンドル・二脚、M79 の照尺） |
| 軍の教範・整備マニュアル（archive.org の TM / FM。パブリックドメイン） | 部品の名前と構造の説明・部品の拡大図 |
| 公表寸法（全長・銃身長・口径・幅） | 縮尺の確認。**互いに独立した寸法 2 つ以上**で合わせ、残りで食い違いが無いか確かめる |

- 写真のライセンスを確かめる（Commons のページの licensetpl）。写真はリポジトリに入れない（トレースした座標だけ）。
  第三者の著作物（競売カタログ等）は作者の了承を取ってからトレースにだけ使う。
- Commons は短時間に続けて取ると 429 になる。1 枚ずつ間を空け、User-Agent に連絡先（個人のメールアドレス）を入れない。
- 写っている物の型・年代を確かめる（別製品・別の型を写さない。A2 グリップを Engage 型で作った例）。
- 型・色・付属品（消音器・二脚・スコープはアタッチメント扱い）で迷ったら作者に聞く。

## 2. 作成

- 側面形はトレース（`trace_<gun>.py` → `<gun>_outline.py`）。光って輪郭が途切れる細い部品（トリガーガード・
  トリガー）は、写真に細かい目盛り（`*_grid.py` 相当）を重ねて読んだ中心線と太さ（`m24._stroke`）で作る。
- 丸い樹脂・木の部品は `inflate_x`（`radius_at` で場所ごとの丸み、`cap_grid` で平らな面を格子で分ける）、
  穴のある部品は `extrude_x_rounded`（`hole_bevel`・片側だけの `side`）。
- ボーンは命名規約（07-model-assets.md）に合わせ、**弾倉 `magazin`・中の弾 `mag_ammo`・操作部
  （`charging_handle`）・セレクター／安全装置（`selector`）・弾倉止め（`mag_release`）は必ず別ボーン**。
- 生成ツール（core 等）を変えたら、他の銃を再生成して形が変わっていないことを確かめる（頂点の比較）。
- 平らな面の三角形・格子の側面・幅の変わる押し出しの側面は、`core` が 1 枚のテクスチャ区画にまとめる（三角形ごとに区画を
  分けると模様が途切れて三角形が浮き出る）。新しい作り方の関数を足すときも、側面は 1 枚の区画にする。
- 筋・模様を見つけたら、形の折れ・陰影（法線。`render(smooth=True)` で保存した法線の陰影）・テクスチャの区画のどれかを切り分ける。

## 3. 指摘チェックリスト（作者のこれまでの指摘）

| # | 確かめること | 元の指摘 |
|---|------------|---------|

## 4. 作成後の確認作業（毎回入れる。省くときは理由を報告）

0. **自動採点** `python3 tools/modelgen/score.py <方式> --photo <トレースに使った写真> --img-dir <scratchpad>`
   （可動部を動かした姿勢も `--pose bone:rx:ry:rz` で）。出るのは**要確認の候補**（写真の付属品・実物どおりの隙間も拾う）。
   候補の場所を下の 1.〜4. の描画で拡大して、本当の不具合かを見分ける。見分けた結果は報告に書く。
1. **写真との重ね**: 同じ縮尺で写真・モデル・半透明の重ねを縦に並べた画像（`*_cmp.py` 相当）。輪郭のずれを見る。
2. **別角度の写真との比較**: 斜め・後ろからの写真と、同じ向きに描いたモデルを並べる。幅・丸み・左右の部品を見る。
3. **継ぎ目**: `joint_views.py`（マゼンタ背景、4 方向）で接合部を拡大。
4. **可動部**: ボーンを動かして描く（`bolt_sim.py` / `pose_sim.py`）。弾倉は外して描く（`mag_view.py`）。
5. **チェックリスト（3.）を 1 行ずつ**。当てはまらない行は飛ばしてよい。
5.5 **実機での確認**（書き出し形式・ローダーに関わる変更をしたとき、作者が実機を見られないとき）: 別リポジトリ
   R0319/Cordite-dev の `tools/autoshot`（Xvfb とソフトウェア OpenGL で実際のクライアントを起動し、データパックの合図で
   画面を撮る）。銃は `models/gun/<ID>.geo.json`・`textures/gun/<ID>.png` に置いて、item_display（空中の大きな銃）と
   一人称で撮る。手元の複製に置くだけで、Cordite-dev にはコミットしない。
   - 一人称は**腰だめと ADS の両方**を撮る。ADS は右クリックの物理押下で入るので、撮る直前に X の偽の入力（XTEST。
     `libXtst` を ctypes で呼ぶ）でボタン 3 を押し、撮ってから離す。作者のファイルを上書きしないよう、試験用の銃 ID
     （`t_*`。gunpack の銃定義も複製）で入れて、終わったら消す。
   - 名前を言ってから持ち替えるまでの間隔は、撮影の遅れ（最大 3 秒）より長くとる（短いと次の銃が写る）。
   - カメラ位置の詰めは、同じ条件（視野角 70°・16:9・カメラ -Z 向き）で描く手元の透視図で回してよい（ゲーム内とほぼ一致した）。
     最後はゲーム内で確かめる。
6. 必要なら**別の目で見る**: サブエージェント（`general-purpose`）に、参考写真と描画を渡して違いを列挙させる
   （作った本人の思い込みを避けるため。必須ではない）。
7. 仕様書（07-model-assets.md の銃ごとの表）を更新し、確認状況（①写真で一致 ②別資料 ③推定）を書く。
8. 作者には「重ね」「別角度」「可動部」の画像を送り、推定の値と未確認の所を明記する。
