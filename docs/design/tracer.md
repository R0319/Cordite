# 曳光弾（トレーサー）🟡 仮

> **範囲**: 弾道の見た目。弾そのもの（命中判定・ダメージ・弾速）は [firing.md](firing.md) / [00-architecture.md](00-architecture.md#ヒット方式弾道シミュレート-)。
> 対象: NeoForge **1.21.1** / パッケージ `net.r0319.cordite`。

## 何を作るか

撃った弾が飛んでいく様子を、**進行方向へ伸びた発光する帯**として表示する。弾丸の3Dモデルは使わない。

## 方式（決定）

### 弾丸モデル（.geo.json）は作らない

曳光弾は「速度方向に伸びた線」であり、その**長さは弾速に依存させたい**。Blockbenchで直方体を1つ置いても、向き合わせも長さの伸縮も結局コード側の計算になり、モデルファイルは器としてしか働かない。板の頂点をコードで組み立てるほうが素直なので、作者が用意するのは**テクスチャ1枚だけ**（それも任意）。

- テクスチャ: `assets/cordite/textures/effect/tracer.png`（要アルファ付きRGBA）。UVは帯の縦方向が進行方向（v=0が先端・v=1が後端）。
- **未作成でも動く**。バニラの白テクスチャ（`minecraft:textures/misc/white.png`）にコード側の色を掛けた単色の帯にフォールバックするので、ミッシングテクスチャにならない。

### サーバーは「1発1パケット」だけ送る

```
サーバー: ProjectileManager#fire
  → GunProjectile を生成（命中判定・ダメージはこちらがサーバー権威で行う）
  → TracerPayload（origin / direction / speed / maxDistance）を
     撃った本人＋周囲のプレイヤーへ送信（sendToPlayersTrackingEntityAndSelf）
        ↓
クライアント: TracerState#spawn
  → ブロックへ1回だけレイキャストして「停止距離」を確定
  → 毎フレーム、経過時間 × 弾速 で先端位置を求めて帯を描く（TracerRenderer）
```

**なぜパケットにしたか**: 以前はサーバーが弾道上に0.5ブロック間隔で`sendParticles`していた。1発あたり数十個のパーティクルパケットが飛ぶうえ、表示は「tick単位で並んだ点」にしかならず滑らかに動かなかった。発射時に1回だけ送ってクライアントが弾速から補間するほうが、帯域も表示品質も良い。

**サーバー権威との関係**: このパケットはサーバー→クライアントの片方向で、載っているのは見た目の情報だけ。クライアントの申告を信用する経路は増えないので、[00-architecture.md](00-architecture.md)の方針と矛盾しない（`GunFiredPayload`と同じ位置づけ）。

### クライアント側は当たり判定を持たない

命中判定はサーバーの`GunProjectile`が持つ。クライアントが決めるのは「どこで止まって見えるか」だけで、**生成時に1回だけ**ブロックへレイキャストして停止距離を求める（毎tickのレイキャストはしない）。

- 壁の向こうまで光が突き抜けて見えない。
- エンティティは貫通して見える（当たっても帯が止まらない）。弾速が速いため1〜2フレームの差でしかないので許容する。

## 主要クラス

| クラス | 役割 |
|-------|------|
| `network.TracerPayload` | S→C。origin(double×3) / direction(float×3) / speed / maxDistance |
| `client.render.TracerState` | 飛行中の曳光弾の保持・停止距離の算出・寿命切れの破棄。MC共通クラスしか使わない（パケットハンドラから触るため） |
| `client.render.TracerRenderer` | `RenderLevelStageEvent`（AFTER_TRANSLUCENT_BLOCKS）での描画。毎tickの`prune`も担当 |
| `combat.ProjectileManager` | 弾丸生成と同時に`TracerPayload`を配信 |

## 調整用の定数（🟡 仮・実機で見ながら調整する値）

`client.render.TracerRenderer`:

| 定数 | 内容 |
|-----|-----|
| `TRACER_LENGTH` | 帯の長さ[ブロック] |
| `TRACER_WIDTH` | 帯の太さ[ブロック] |
| `TRACER_HEAD_SIZE` | 先端の発光点の一辺[ブロック]（下記） |
| `TRACER_COLOR` | 色（オレンジ）。テクスチャがある場合は乗算される |
| `MIN_CAMERA_DISTANCE` | カメラからこの距離[ブロック]より内側には描かない（既定5.0）。自分の弾は**目の位置から出る**ため、これが無いと「頭から弾が出ている」ように見える。帯は手前側を切り詰めて描くので、この距離から生えてくるように見える（丸ごと消すと、先端が最小距離に達した瞬間に帯がまとめて現れてしまう） |

## ⚠️ 帯だけでは自分の弾が見えない（先端の発光点が要る）

帯の横方向は `進行方向 × カメラへの方向` で求める（進行方向を軸にカメラを向く板）。ところが**自分が撃った弾は視線の正面へ飛んでいく**ので、この2つのベクトルが平行になり**外積がゼロ＝帯の幅が0**になる。ゼロ割回避で描画をスキップしていたため、他人の弾（横から見る）は見えるのに**自分の弾は一度も描画されない**という状態になっていた。

対処として、

- 外積が潰れる場合は任意の直交軸で代用し、帯自体は必ず作る（画面上では点に潰れる）。
- **先端に常にカメラを向く発光点（`TRACER_HEAD_SIZE`）を描く**。これで正面へ飛ぶ弾も「遠ざかっていく光の点」として見える。

真横から見れば従来どおり帯として尾を引く。

## 着弾エフェクト

命中した瞬間に、サーバー側（`GunProjectile#spawnBlockImpact` / `#spawnEntityImpact`）で`sendParticles`する。

- **ブロック**: 当たったブロックの破片（`ParticleTypes.BLOCK`）＋煙を1回。当たった面の法線方向へ少しずらして出す（ずらさないとブロックの内側に埋まって見えない）。
- **エンティティ**: 小さな粒子を1回（バニラのダメージ表示に上乗せ）。

曳光弾と違ってサーバーからパーティクルを撒いている理由は、**着弾は1点で1回だけ**なので軽く、かつ周囲のプレイヤーにも見える必要があるから（弾道全体に撒いていた頃の「1発で数十パケット」にはならない）。粒子数・勢いは`GunProjectile`の`IMPACT_*`定数（🟡仮）。

## 動作確認

`./gradlew runClient`:

1. 左クリックで撃つと、**自分の正面へ飛んでいく光の点**が見える（点が並ぶのではなく、フレーム単位で滑らかに動く）。真横へ撃った弾を見ると帯として尾を引く。
2. 壁を撃つと帯は壁で止まり、向こう側へ突き抜けない。着弾点にブロックの破片と煙が出る。
3. エンティティに当たると命中位置に粒子が出る。
4. 暗い場所でも帯が明るいまま見える。
5. 自分の発射の瞬間、画面いっぱいに帯が映り込まない。
6. マルチプレイで、他プレイヤーの発射も同じように見える。
7. `textures/effect/tracer.png` を置くと見た目がそれに差し替わる。置かなくてもオレンジの単色として動く。
